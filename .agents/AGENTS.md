# pstack 维护规范

## 唯一维护源

- 只在本 fork 的 `custom` 分支修改 pstack，工作副本为 `~/code/pstack/`。
- `skills/` 是技能源码。`~/.agents/skills/` 是安装产物，不直接修改，也不从那里复制回源码。
- 不手动修改安装锁文件来表示已经安装。安装记录由真实的 `npx skills` 调用生成。
- 全局用户指令、模型角色配置和其他来源的技能不纳入本公共 fork。

## 固定执行顺序

1. 检查分支和工作区，保留其他任务尚未提交的改动。
2. 在 fork 中修改相关技能，审查差异，执行适合该变更的检查。
3. 只提交本次修改，并执行 `git push origin custom`。
4. 推送成功后运行 `python3 scripts/reinstall_skills.py <技能名>`。多个技能用空格分隔；省略名称会重装本仓库全部顶层技能。
5. 确认脚本返回成功，报告源提交、重装的技能和文件核对结果。

脚本要求工作区干净、当前分支为 `custom`，且本地 HEAD 与真实远端 `origin/custom` 相同。它用 `npx skills` 从该提交重新安装，随后核对实际文件和安装来源。检查失败时停止，不用复制文件或修改锁文件绕过检查。

发现安装目录已有未纳入 Git 的编辑时，先展示差异，确认要保留的内容，再将相同修改应用到 fork。不要直接重装覆盖这些编辑。

## 上游更新

`origin` 是 `cbingb666/pstack`，`upstream` 是 `backnotprop/pstack`。上游升级单独审阅并合并到 `custom`，随后执行相同的提交、推送、重装和核对流程。不强制推送，也不顺带升级未审阅的上游变更。

操作示例见 [维护说明](../LOCAL-MAINTENANCE.md)。
